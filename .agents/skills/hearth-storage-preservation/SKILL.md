# Hearth and Haul storage preservation

Read AGENTS.md, docs/STATUS.md, docs/SOURCE-RECOVERY.md, docs/PROVENANCE.md, docs/COMPATIBILITY.md and docs/TESTING.md. This repository distinguishes recovered historical evidence from newly reproduced tests.

## Establish the actual buildable lineage

Locate the authorized Backpacks2.0.2.4 source package and compare its exact size/digest with the documented checkpoint. Inspect cleaned-publication contents and original attribution before importing. Preserve Java/resources, Gradle configuration, conversion and QA tooling; exclude private storage references, caches and runtime logs. Do not replace the full Git tree with only imported files.

Use the recovered build instructions and exact dependency versions, not a guessed Gradle command in the documentation hub. Preserve sqst_bkpk registry/save identity, existing Warden/Bee/Creaking content and Scai Quest attribution. A current dependency release is a candidate for testing, not evidence that old compatibility certificates still hold.

## Protect storage and optional integration boundaries

Trace inventory serialization, ownership, equipped/unequipped state, item transfers and compatibility adapters before editing. Sophisticated or Curios integration must have a defined optional boundary; missing integration should not corrupt ordinary backpack contents. Expanded variants and dimensional homes remain independent roadmap features until implemented.

Test legal and rejected inventory moves, nested storage, full inventories, death/drop/recovery and save/reload with representative old data. Confirm rejected operations neither duplicate nor lose items. Exercise single-player and multiplayer ownership separately. Do not perform destructive checks on an owner's only world or inventory.

For future dimensional entry/exit work, test return coordinates, ownership, restart while inside, failed transition and recovery; a GUI opening or a server boot is insufficient.

## Evidence and publication

Separate compilation, packaged-server startup, client rendering, gameplay, persistence, nesting safety and multiplayer results. Reproduce the applicable recovered regression tools and record actual artifact/dependency hashes, date and environment. Retain historical certificates as history rather than relabeling them freshly passed.

Preserve last-good source/artifacts/world backups. Maintain existing documentation and credits when importing source; inspect complete diffs for unintended deletion. Publish only approved assets and source, verify remote files and live wiki, and record unresolved runtime gates instead of declaring a release from a ZIP.
